# Next-version client contract (development)

All control remains on the authenticated TV / calibration-role connections. A client opts in with hello `client_protocol: 1`. Existing calibration messages and TV remote messages remain compatible. New client request IDs are monotonic within the connection and independent of old TV remote request IDs. Phone's existing `id` counter is shared across its request types.

## Requests and status

Send `{"op":"client_request","id":1,"action":"browse","provider":"windows","entry":"","cursor":0}`. Reply is `{"op":"client_response","reply":1,"ok":true,"error":"","result":{...}}`. Status broadcasts are `{"op":"client_state","state":{...}}`; initial welcome includes `client_protocol:1`. UI must keep timing/status readers free while a request runs. Read-only provider browsing uses separate bounded workers so it cannot hold the transport operation lock. Client-state catalogs are bounded below the 64 KiB frame limit and retain selected tracks when truncation is necessary. Slow browse/load operations use the host operation worker; responses can arrive out of order and must be matched to request IDs. Duplicate/old-session requests are rejected.

Actions: `providers`; `browse` (provider, opaque entry, cursor); `load_entry` (provider, opaque entry, autoplay boolean); `track` (aid); `subtitle` (sid, with `off` to disable); `play`; `pause`; `seek` (seconds, play_after optional); `resync`; `storage_unregister` (only the requesting Android peer’s own source). Mutating current-media operations include current `epoch` and `media_generation` from state, so stale track menus do not change a replacement movie. Browse and load_entry do not require an existing movie.

Client state fields: `state`, `epoch`, `media_generation`, `loaded`, `title`, `position_ms`, `duration_ms`, `video_lead_ms`, `audio_tracks`, `subtitle_tracks`, `selected_subtitle`, `audio_badge`, `providers`, `can_control` and bounded safe `error`. Audio tracks: `id`, `label`, `language`, `codec`, `selected`, `supported`, `format_label`. IDs are strings, labels are display strings. Subtitle IDs are TV text-group IDs: `<group>:<track>` indices in current Media3 text groups, stable within a media generation; `off` is an explicit choice. TV status supplies `subtitle_tracks` with the same fields and `selected_subtitle`. Host selection requests send TV op `subtitle`, sid, current epoch. Changing a subtitle does not independently seek/resume video. Audio track switches retain coordinated pause/prepare/resume and verify compressed passthrough.

Browse result: `provider`, `entry`, `parent` (opaque ID or empty), `label`, `entries` (up to 100), `next_cursor` (integer or null). Each entry has `id`, `name`, `directory` and optional `size`. Providers: `id`, `label`, `available`. Windows provider root lists user-shared folders; opaque IDs are resolved only within those roots. Only local Windows setup can add/remove shared filesystem roots (`library_add` with path; `library_remove` with root ID). Remote clients cannot change grants.

## Android storage provider

Both TV and phone use the shared Android storage module, with an explicit ACTION_OPEN_DOCUMENT_TREE read grant. On foreground connection, start its bounded HTTP range server and send `{"op":"storage_register","id":2,"port":12345,"token":"random-per-server-capability","label":"Phone storage"}`. Provider identity is derived from authenticated connection role (`phone` / `tv`); host derives the network address from that socket, never a client-supplied URL/address. Registration replies `client_response`. Disconnect/foreground stop closes and unregisters that provider. A connected phone need not share storage to select tracks or calibrate.

Provider HTTP URLs: `http://<peer-address>:<port>/<token>/browse?entry=<opaque-id>&cursor=0` returns the browse result above; `/<token>/file/<opaque-id>` supports GET/HEAD and single byte ranges with Content-Length, Accept-Ranges, 206/Content-Range and 416. IDs are token-safe opaque random strings, never document URIs or paths. Browsed file entries include `size` (positive integer) and `seekable` true only when supported; unsupported providers are rejected with guidance. Host snapshots authenticated provider/file identity before serving; proxies original bytes to TV/mpv with bounded reads, no transcoding, no credentials in diagnostics. A detached provider cannot be used for a future load. Host loads Android media through its own tokenized media URL for both mpv and TV; no unrelated URL can be supplied through the client protocol.

Android root API (implemented by root agent): `new dev.dualtheater.shared.StorageShare(Context)`; `setTree(Uri)` persists the chosen read grant/tree; `hasTree()`; `start()` returns registration JSONObject with op/port/token/label (caller adds id and sets label); `close()` stops HTTP service but keeps the selected tree. `pickerIntent()` returns the tree-picker Intent. Caller handles ACTION result with takePersistableUriPermission then setTree, and starts/registers only while the authenticated client is foreground. Root owns this module and Gradle wiring.

## UI conventions

Shared palette: background `#101827`, card `#1B293D`, accent `#45D7C8`, text `#F4F7FB`, secondary `#B8C6D9`, warning `#FFCC80`, error `#FF9292`. Clear sections: Connect, Library, Player, Calibration (phone), Settings/help. TV overlays use remote-focusable buttons, Back dismisses menus first, Up opens playback options, left/right and center retain their existing transport semantics when menus are closed. Startup/track-change badge in top right is small, timed and metadata-qualified. No proprietary logos required; use readable original text badges.
